# 确认、锁定和修订

## 确认政策
新项目默认把音乐试听、代表动效样片设为必须用户确认的创作节点；脚本与其余预览由代理实际审阅后推进。用户要求先确认脚本、逐镜确认或封面时，将对应项目加入 work/review-ledger.json 的 required_user_gates；逐镜确认另保存 shot-approvals.json，绑定镜头资产和预览哈希。明确委托自主决定时记录原话与来源，调整确认政策，沿用委托，不重复提问。新主题不自动继承本主题的音乐或审美选择。

一次确认尽量打包为可比较的具体材料。不要把“用了这首歌”等同于“任何剪辑点、音量均已同意”。不为内部可逆操作增加批准流程。

## 必须准备的音乐确认包
1. 选曲：曲名、版本/演奏者、原始来源、实际可用本地文件和授权核验范围。未知授权写未知，用户指定不等于商用授权。
2. 剪辑：原曲开始/结束时码；高潮在原曲与成片中的时码；完整音乐结构和目标片长。
3. 音量：实际处理增益、淡入/淡出，有旁白时另做混音；相对降6dB等修改要比较相同音乐区间。
4. 试听：生成实际处理后的音频及开头到高潮之后的有声视频，不能只有文字表格。25秒高潮的例子应至少预览到30–35秒。
5. 用户选择具体版本后，将确认原话、消息/回合定位、试听文件、music-plan.json、实际母带和其SHA256一起记录。选曲和剪辑试听可一次确认。
6. 总时长、起点、变速、音量、淡入淡出或混音改变时重做受影响试听。改画面/诗词且音频未动时，保留确认并核验音轨一致，避免重复询问。

source_climax - excerpt_start = video_climax 仅对连续、未变速、无拼接片段成立。变速/拼接须用逐段映射计算并实际预览。不能为了目标时码凭空填节拍网格。自动谱峰和网格只能当候选，重音依据写进cue表。

## 记录工具
先运行：
```text
python -I scripts/production_gate.py init <工程>
```
记录**实际已有**确认/审阅：
```text
python -I scripts/production_gate.py record <工程> --gate music --actor user --statement "用户确认具体试听版本的原话" --source-ref "本任务消息定位" --file work/music-preview.mp4 --file music-plan.json
python -I scripts/production_gate.py check <工程> --stage motion
```
逐镜确认模式由policy.shot_approval=each启用；可用policy.shot_ids指定待确认镜头，否则覆盖所有main镜头。每个真实确认使用record-shot子命令，传入--shot-id、--statement、--source-ref、--file。换该镜头资产/时长/渲染器时原记录失效。

music自动绑定project.audio、fps、总帧数和实际音频。preview/visual自动绑定public、src、根目录mjs及依赖锁文件；额外文件也参与哈希。文件一变，该记录失效。content/look必须主动传入实际文案/来源和样片文件，不能只绑定一份自评文字。

ledger是可追踪的本地记录，不是身份认证或防篡改签名。脚本无法证明一段原话确来自用户，也无法判定美感。禁止代理杜撰确认或把工具exit=0当作用户批准。测试夹具中的模拟确认不能迁移为真实项目确认。

## 最终状态
制作完成可先交付具体MP4供验收：stage=delivered_pending_acceptance。只有用户明确认可对应版本，才写accepted。送达、机器QC通过、代理视觉审阅、用户认可分开记录。历史项目可作为案例，不补造当时没有记录的审批证据。

## 修订影响
- 换曲/选段/变速：音乐、cue、时长、分镜、预览和最终QC重核。
- 只调音量：重出试听并重核音频；保持已确认画面节奏，除非时长有变。
- 换一张素材：该镜头细节/alpha/运动与相邻切换复核，最终媒体QC重做；不重新要求整套音乐确认。
- 加诗词：核对原文、作者、篇名、来源；短镜头只放读得完的句子；文字独立动画，检查避让。可核验的古籍/诗词是可选主题模块，不是所有新主题必加。
- 封面修订：只影响封面；保留标题/人物决定，依据用户新参考直接改。此次偏好是片尾四季分屏，应在本项目样式记录中保留，不写成所有主题都必须四季分屏。
